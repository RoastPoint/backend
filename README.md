# RoastPoint — учебный MVP кофейни

Java 25, Spring Boot 3.5.16, Spring JDBC, Spring Security, PostgreSQL 17.

## Запуск

Перед первым запуском задайте начальный пароль тестовых пользователей:

```powershell
$env:DEMO_PASSWORD='Coffee-Demo-2026!'
docker compose up --build -d
docker compose logs -f app
```

Пароль: от 12 символов до 72 байт UTF-8. Логины: cashier1, barista1, admin1.
DEMO_PASSWORD применяется однократно к исходным аккаунтам, включая старые маркеры
DEMO_NOT_A_REAL_HASH. В БД сохраняется BCrypt с cost=12. Повторный запуск пароль
не меняет. Без DEMO_PASSWORD назначаются неизвестные случайные пароли, поэтому
задайте переменную до первого старта. Управление пользователями в MVP не входит.

Для IDEA: JDK 25, БД (`docker compose up -d db`), DEMO_PASSWORD в конфигурации
запуска, main класса RoastPointApplication. Настройки: DB_URL, DB_USER,
DB_PASSWORD; по умолчанию localhost:5432/coffee_shop, postgres/postgres.
При старте schema.sql и migration.sql обновляют схему без удаления заказов.
Инициализацию выполняет один экземпляр приложения. DB_INIT_MODE=never допустим
только после применения обоих SQL-файлов. Сборка: `mvn test`, `mvn package`.

## Сценарии и роли

| Действие | Кассир | Бариста | Администратор |
| --- | --- | --- | --- |
| Меню, заказы, очередь | Да | Да | Да |
| Создание заказа | Да | Нет | Нет |
| accepted → preparing → ready | Нет | Да | Нет |
| ready → issued | Да | Нет | Нет |
| Добавление категорий, создание и изменение меню | Нет | Нет | Да |
| Отчёт | Нет | Нет | Да |

Кассир определяется из сессии. Поле cashierId больше не принимается.
Цена и название сохраняются из меню; последующие правки меню не меняют историю.
Недоступную позицию заказать нельзя. Чтобы убрать позицию из продажи,
администратор устанавливает available=false. Переходы статусов последовательные,
обратные и повторные переходы дают 409. Транзакции и блокировки защищают от гонок.
Оплата, склад, отмена и возвраты за пределами выбранного учебного MVP.
Отчёт показывает стоимость выданных заказов, а не подтверждённые платежи.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/auth/csrf | CSRF-токен и cookie сессии |
| POST | /api/auth/login | Вход: form-urlencoded, login и password |
| GET | /api/auth/me | Текущий логин и роли |
| POST | /api/auth/logout | Выход, 204 |
| GET, POST | /api/menu/categories | Список / добавление категории: name |
| GET, POST | /api/menu | Список / добавление позиции |
| GET, PUT | /api/menu/{id} | Чтение / изменение позиции |
| POST | /api/orders | Создать заказ, 201 и Location |
| GET | /api/orders/{id} | Заказ с позициями и суммой |
| GET | /api/orders?status=accepted&limit=50&offset=0 | Очередь; status необязателен, limit 1–100 |
| PATCH | /api/orders/{id}/status | preparing, ready, issued |
| GET | /api/reports/sales?from=2026-10-01&to=2026-10-31 | Отчёт по включительному периоду, до 366 дней |

Тело заказа: `{"items":[{"menuItemId":3,"quantity":2}]}`.
Тело меню: `{"categoryId":1,"name":"Капучино","price":200.00,"available":true}`.
Тело статуса: `{"status":"preparing"}`.

Сессия: cookie JSESSIONID, таймаут бездействия 30 минут. Перед входом получите
/api/auth/csrf; для POST/PUT/PATCH отправляйте token в заголовке headerName.
После входа получите новый CSRF-токен: Spring Security обновляет сессию и
сбрасывает прежний токен. Сохраняйте cookie между запросами.
В HTTPS задайте SESSION_COOKIE_SECURE=true.

Ошибки: 400 — валидация/JSON; 401 — требуется вход/неверный пароль; 403 —
роль/CSRF; 404 — объект не найден; 409 — недоступная позиция, переход статуса
или ограничение БД; 503 — БД недоступна. JSON: timestamp, status, message, details.
Неизвестные JSON-поля и дробные значения целочисленных полей отклоняются.
Заказ содержит 1–100 уникальных позиций, количество 1–1000. Цена неотрицательная,
максимум два знака после запятой. Названия непустые. Внешние ключи защищают связи.

## База данных и проверка

migration.sql добавляет ready, время выдачи, снимок названия позиции, ограничения,
индексы, триггер переходов статуса и представления order_totals, daily_sales,
product_sales. Для старых выданных заказов неизвестное время выдачи однократно
заменяется временем создания, название восстанавливается из текущего меню.
Дни отчёта считаются по времени PostgreSQL (timestamp без часового пояса).
Запросы по дням, товарам и кассирам: src/main/resources/reports.sql.

`mvn test` проверяет HTTP-контракт, валидацию, вход, выход, CSRF и права ролей.
`.\check-api.ps1` проверяет полный цикл с PostgreSQL на запущенном приложении,
используя DEMO_PASSWORD, и создаёт один заказ. Примеры запросов: requests.http.
